# Plutus Lite 要件定義書(パイロット用ワンページャー)

Nov 5, 2026 · @Tak

Plutus の基礎機能だけを切り出した家計簿アプリを、新規開発編フライホイールの手順で一から構築し、手順書の検証に使う

## 1. 解く課題と利用者

- 利用者は本人1名(Googleアカウントのメール許可リストで制限)
- 課題: 日々の支出と収入を記録し、月ごと、カテゴリごとの金額を確認したい

## 2. 機能(スコープ内)

1. Googleログイン(Firebase Authentication)と許可リスト
2. 取引の登録・編集・削除: 日付, 種別(支出/収入), 金額(円, 負数可), カテゴリ, メモ
3. 取引一覧: 月で絞り込み、日付の降順
4. 月次サマリー: 月ごとの収入合計, 支出合計, 支出のカテゴリ別内訳(棒グラフ)
5. ユーザー分離: すべての読み書きをサーバー側で確定したUIDで絞り込む
6. レート制限: エンドポイントごと

## 3. スコープ外(やらないこと)

投資, 資産管理, 外貨, 按分, 予算, AIによるカテゴリ予測, Slack連携, Text2SQL, Gmail取込, 照合エージェント, CSV取込, 複数ユーザー対応

## 4. 受入条件

| ID | 条件 | 確認方法 |
| --- | --- | --- |
| A1 | 許可リスト外のアカウントはAPIが401または403を返す | APIテスト |
| A2 | 取引を登録、編集、削除でき、一覧に反映される | APIテスト, E2E |
| A3 | 他ユーザーのデータが、トークンが有効でも取得できない | APIテスト(2ユーザー) |
| A4 | 月次サマリーの合計が、一覧の合計と一致する | 固定データでの照合テスト |
| A5 | 金額は整数円で扱い、負数を許容する。不正な値は400を返す | 入力検証テスト |
| A6 | 集計はSQLまたはPythonで計算し、画面側で再計算しない | レビュー |
| A7 | Terraformでゼロから環境を再作成できる | 空のプロジェクトでの実行 |

## 5. 制約と技術構成

- 構成: Next.js(TypeScript), FastAPI(Python 3.12), BigQuery, Firebase Authentication, Cloud Run, Terraform, Cloud Build
- 取引テーブル項目: transaction\_id, user\_id, date, type, amount\_jpy, category, note, created\_at
- 予算, 期限, 利用するGCPプロジェクト: 未確定(着手前に確認する)

## 6. 用語とデータの入手元

- 支出/収入: type で区別する。金額は常に円の整数
- 取引の入力元は画面からの手入力のみ。既存データの移行は行わない

## 7. パイロットとしての計測項目

工程ごとの所要時間, 人の関門で待った時間, 差し戻し回数, AIが生成した成果物の修正量を記録し、手順書の改訂に使う。
