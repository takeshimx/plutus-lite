# 評価基盤(P5)

API が受入条件を満たしているかを自動で判定する。正解(golden set)は実装より先に決め、関門G5で人が承認する。プロダクトに LLM を使わないため、judge は使わず、すべて値の一致で判定する。

## ファイル

| ファイル | 内容 | 変更 |
| --- | --- | --- |
| `golden/dataset.json` | 固定の取引データ(2ユーザー分) | G5 の承認が必要 |
| `golden/expected.json` | 正解の値。`make_expected.py` で計算する | G5 の承認が必要。手で書き換えない |
| `golden/make_expected.py` | 正解を計算するスクリプト。アプリのコードを使わない | G5 の承認が必要 |

## 金額の決まり(2026-11-17 決定)

- 金額は符号付きの整数円。合計は、種別ごとに金額をそのまま足す
- 支出のマイナスは返金。支出合計とカテゴリ別内訳から差し引く(例: 交通費 3,000 と −1,000 → 交通費 2,000)
- 収入のマイナスは訂正。収入合計から差し引く
- 月次サマリーには、支出のカテゴリ別内訳を含める。並び順は金額の大きい順、同額ならカテゴリ名の順
- 取引が1件もない月は、サマリーに出さない

## golden set の正解(user_a)

| 月 | 収入合計 | 支出合計 | 支出のカテゴリ別内訳 | 一覧の件数 |
| --- | ---: | ---: | --- | ---: |
| 2026-12 | 0 | 2,000 | 食費 2,000 | 1 |
| 2026-11 | 295,000 | 16,200 | 日用品 8,000 / 食費 6,200 / 交通費 2,000 | 7 |
| 2026-10 | 300,000 | 4,000 | 食費 4,000 | 2 |

計算の内訳(2026-11)

- 収入: 300,000(給与)− 5,000(訂正)= 295,000
- 支出: 1,200 + 5,000(食費)+ 3,000 − 1,000(交通費、返金あり)+ 8,000(日用品)= 16,200

user_b(2026-11): 収入 500,000、支出 99,999。user_a の結果に、user_b の値が混ざらないことを確かめる。

## テストケース

API は `/api` 配下(docs/design.md.md の 3節)。

| ID | 受入条件 | Given | When | Then |
| --- | --- | --- | --- | --- |
| E01 | A1 | トークン無し | 各エンドポイントを呼ぶ | 401 |
| E02 | A1 | 無効なトークン | 各エンドポイントを呼ぶ | 401 |
| E03 | A1 | 有効だが許可リスト外のアカウント | 各エンドポイントを呼ぶ | 403 |
| E04 | A2 | user_a でログイン | 取引を登録する | 201。一覧に現れる |
| E05 | A2 | E04 の取引 | 金額を編集する | 200。一覧の金額が変わる |
| E06 | A2 | E04 の取引 | 削除する | 204。一覧から消える |
| E07 | A3 | user_a と user_b の golden set | user_b で、user_a の取引IDを編集・削除する | 404。user_a の取引は変わらない |
| E08 | A3 | 同上 | user_a で一覧とサマリーを取得する | user_b の取引(b01、b02)が含まれない |
| E09 | A2 | golden set | user_a で `month=2026-11` の一覧を取得する | 7件。日付の降順(a09 → a03) |
| E10 | A4 | golden set | user_a で月次サマリーを取得する | 上の正解表と完全に一致する |
| E11 | A4 | golden set | 各月の一覧の合計を、種別ごとに計算する | サマリーの合計と一致する |
| E12 | A5 | user_a でログイン | 金額 −1,000 の支出を登録する | 201(負数を受け付ける) |
| E13 | A5 | 同上 | 金額 1.5 / "100"(文字列)/ 無し | 400。何も保存されない |
| E14 | A5 | 同上 | type が income、expense 以外 | 400 |
| E15 | A5 | 同上 | 日付が 2026-02-30 / 2026-13-01 / 空 | 400 |
| E16 | A5 | 同上 | メモが201文字 / カテゴリが無し | 400 |
| E17 | A5 | 同上 | リクエストに user_id を含めて登録する | user_id は無視され、トークンの UID で保存される |
| E18 | A5 | 同上 | 金額 0 / カテゴリが空文字 | 400 |
| E19 | A5 | 同上 | 金額 10,000,000,000 と −10,000,000,000 | 201(上限ちょうどは受け付ける) |
| E20 | A5 | 同上 | 金額 10,000,000,001 と −10,000,000,001 | 400 |

A6(画面で再計算しない)はコードレビューで確認する。A7 は P4 で確認済み(`infra/README.md`)。

## G5 での決定(2026-11-17)

| 項目 | 決定 |
| --- | --- |
| 金額 0 | 400 で拒否する(意味のない取引のため) |
| 金額の上限 | 絶対値が 100億円(10,000,000,000)を超えたら 400 |
| カテゴリが空文字 | 400(必須項目のため) |
| 合格基準 | 実装済みの機能について、全ケースが合格すること(1件でも失敗したら PR をブロック) |
| 必須にする時期 | 機能を実装した PR から、その機能のケースを必須にする。未実装の機能のケースは、実装されるまで対象外 |
